### 1. Signature is checked against a parsed (re-serialised) body

**🟠 High** · definite · `app/api/stripe/webhook/route.ts:11` · rule H2

```
const event = stripe.webhooks.constructEvent(JSON.stringify(body), sig, process.env.STRIPE_WEBHOOK_SECRET!);
```

**Why it matters.** express.json()/bodyParser has already parsed the body, so the bytes no longer match what Stripe signed. Verification fails at random; teams often 'fix' it by turning verification off.

**Fix.** Mount express.raw({ type: 'application/json' }) on the webhook route only (before any global JSON parser) and pass that Buffer to constructEvent.

### 2. Edge runtime with synchronous constructEvent

**🟠 High** · definite · `app/api/stripe/webhook/route.ts:5` · rule H3

```
export const runtime = "edge";
```

**Why it matters.** The sync verifier needs Node's crypto; on the Edge runtime it throws, so every webhook fails with 400 and Stripe eventually disables the endpoint.

**Fix.** Use `export const runtime = 'nodejs'` for the webhook route, or switch to `await stripe.webhooks.constructEventAsync(...)`.

### 3. No sign of duplicate-event protection

**🟠 High** · likely, needs a human look · `app/api/stripe/webhook/route.ts:13` · rule H4

**Why it matters.** Stripe delivers events at least once. Without recording event.id, a retry or resend runs side effects again: double credits, duplicate emails, two provisioning runs.

**Fix.** Insert event.id into a table with a unique key (ON CONFLICT DO NOTHING) in the same transaction as the side effect, and skip events already recorded.

### 4. Failed renewals are not handled (no invoice.payment_failed)

**🟡 Medium** · definite · `app/api/stripe/webhook/route.ts:13` · rule H6

**Why it matters.** You can't warn the customer or apply a grace period, so access either continues unpaid or stops with no explanation.

**Fix.** Handle invoice.payment_failed: re-sync the subscription (it becomes past_due) and notify the customer.

### 5. Subscription state is taken straight from the event payload

**🟡 Medium** · likely, needs a human look · `app/api/stripe/webhook/route.ts:14` · rule H8

```
const sub = event.data.object as Stripe.Subscription;
```

**Why it matters.** Stripe does not guarantee delivery order. An older 'customer.subscription.updated' arriving late overwrites newer state (e.g. re-activates a canceled customer).

**Fix.** On each event, fetch the latest subscription with stripe.subscriptions.retrieve(id) and write it only if it is not older than what you stored (compare event.created).

### 6. No reconciliation job (nothing lists subscriptions from Stripe)

**⚪ Low** · likely, needs a human look · `app/api/stripe/webhook/route.ts:13` · rule H9

**Why it matters.** If a webhook is never delivered (endpoint down, deploy, misconfiguration), a paying customer stays without access until they complain.

**Fix.** Run a scheduled job that lists subscriptions from Stripe and repairs any that differ from your database, through the same code path as webhooks.
